# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static marketing site for **Emberfox Games** (domain `emberfox.online`, repo published via GitHub Pages as `robmat.github.io`). It is a landing page listing the studio's Android games with Google Play links, plus standalone privacy policy and support pages, and an unrelated tool app under `bn/` (see below). No framework, no JS bundler, no tests — plain HTML + Tailwind CSS v3 (CLI). The owner plans to grow and modernize the site, so expect structural changes to the workflow below.

## Commands

```bash
npm install                                                       # installs tailwindcss CLI
npx tailwindcss -i ./src/input.css -o ./dist/output.css --watch   # dev watch (same as tailwind.sh / tailwind.ps1)
npx tailwindcss -i ./src/input.css -o ./dist/output.css           # one-off build
./deploy.sh                                                       # or deploy.ps1 — copies src/index.html to ./index.html
```

`deploy.sh` / `deploy.ps1` wait for a keypress at the end, so they hang when run non-interactively. "Deploy" only produces the root `index.html`; actual publishing is committing and pushing to `master` (GitHub Pages serves the repo root).

## Source vs. published files

- **Edit `src/index.html`, never the root `index.html` directly.** The root file is generated by the deploy script, which copies `src/index.html` and strips every `../` so asset paths resolve from the repo root (`../media/x.png` → `media/x.png`, `../dist/output.css` → `dist/output.css`). Anything in the source that legitimately needs `../` will be broken by this blind replace.
- Opening `src/index.html` directly in a browser works for previewing because of those `../` paths.
- `dist/output.css` is a committed build artifact — rebuild it after changing Tailwind classes and commit it along with the HTML.
- Tailwind's `content` glob only scans `./src/**/*.{html,js}`. Classes used only in root-level files are **not** generated — `support.html` currently uses several such classes (e.g. `bg-stone-800`, `px-8`, `gap-3`) that are missing from `dist/output.css`. Widen the glob (e.g. add `./*.html`) and rebuild when touching root pages.
- `support.html` is a hand-written root page (not in `src/`, no deploy step) that uses `dist/output.css` with root-relative paths and links back to `/`. Despite the generic name, its content is the support/FAQ page for one iOS game, *Arrows Untangle*.
- `privacy_policy.html` lives only at the root, is not part of the src→deploy flow, and uses its own inline `<style>` instead of Tailwind. It isn't linked from `index.html`; its URL is most likely what the Play Store listings point to, so don't move or rename it.
- `app-ads.txt` (AdMob seller declaration) and `.htaccess` (anti-hotlinking for `emberfox.online`) must stay at the site root.

## Game cards

The game grid in `src/index.html` sits between `<!--GENERATED START -->` and `<!--GENERATED END -->`. The generator is not in this repo; cards are currently maintained by hand by copying an existing card. Each card repeats the same block: Google Play SVG icon, `play_store_graphic.png` banner link, and `launcher.png` + title link.

Each game has a folder `media/<game>/` with `launcher.png`, `play_store_graphic.png`, `app_id.txt` (Android package id, used in the Play URL `https://play.app.goo.gl/?link=https://play.google.com/store/apps/details?id=<app_id>`), and `app_name.txt`. The displayed card title does not always match `app_name.txt`.

## Analytics / consent

The `<head>` of `src/index.html` sets up Google Ads gtag (`AW-959467352`) with Consent Mode v2: all consent defaults to `denied`, the `#cookieConsent` banner's button calls `window.acceptCookies()` which grants consent and stores `consentGranted` in `localStorage`. Every outbound Play Store / mailto link fires a `conversion` event via an inline `onclick`. Enhanced conversions are fed a randomly generated fake email (`generateRandomEmail()`) — this is deliberate existing behavior, not a bug to silently "fix"; ask before changing tracking.

## `bn/` — Battle Nations fight simulator

A self-contained vanilla-JS app (served at `/bn/`), independent of the Emberfox site: it doesn't use Tailwind, `dist/`, or the deploy script, and has its own `style.css`. It simulates fights between player units (Pelicans, Mega Tank) and boss NPCs (the composite Goliath Tank, whose sub-units are defined in `GOLIATH_VARIANTS` in `app.js`) from the game *Battle Nations*. Scripts are loaded as plain `<script>` tags in a fixed order, each exposing a global:

- `wiki.js` → `window.WikiFetcher`: at runtime, fetches unit pages from the Miraheze wiki MediaWiki API (`battlenations.miraheze.org`, `origin=*` for CORS) and parses the wikitext templates (`UnitProfile`, `UnitRanksBox`, `WeaponBoxTabber`, …) into stats. Unit stats come from the live wiki, not from files in the repo.
- `sim.js` → `window.SimEngine`: pure simulation engine with no DOM access (turns, cooldowns, damage/resistance, targeting).
- `patterns.js` → `window.ATTACK_PATTERNS`: attack tile patterns. This is an inlined copy of `assets/patterns.json` (whose `_notes` key documents the grid/targeting format), kept inline so the page works over `file://` where `fetch()` of local files is blocked. Keep the two in sync.
- `app.js`: UI — board/tray, drag-to-resize panels, controls, battle log, tooltips; wires the three modules together.

The `#version-tag` text at the bottom of `bn/index.html` (date + short commit hash) is edited by hand; there is no build step that updates it.
